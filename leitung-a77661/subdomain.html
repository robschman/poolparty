Kurz zur Einordnung

Deine Aufteilung ist richtig: Sport über schrittfuerschrittfit.at, alles andere über robschman.at. Eine Kindergeburtstagsfeier hat auf der Domain deiner Fitnessmarke ohnehin nichts verloren — schon gar nicht, weil dort gewerbliche Inhalte stehen und hier etwas rein Privates dazukäme.

Dazu muss ich mich korrigieren

Ich habe gesagt, die Subdomain bei schrittfuerschrittfit.at „kostet nichts extra“. Das war zu schnell geschossen. In deinem eigenen Memo zu robschman programming steht: Das SSL-Kontingent des IONOS-Pakets ist mit 3 von 3 aufgebraucht — genau deshalb ist robschman.at im August auf GitHub Pages umgezogen, statt 3,36 € im Monat für ein viertes Zertifikat zu zahlen.

Ob eine Subdomain auf dem Webspace ein weiteres Zertifikat verbraucht oder mit abgedeckt ist, weiß ich nicht sicher — das siehst du erst im Kundenbereich. Der Weg unten umgeht die Frage komplett.

A

Weg A — GitHub Pages

Mein Vorschlag · etwa 20 Minuten Arbeit, dann warten

Genau so, wie robschman.at selbst läuft. Das Zertifikat kommt gratis von GitHub und erneuert sich allein — die SSL-Frage stellt sich gar nicht.

1. Neues Repository anlegen

  1. Auf github.com anmelden, oben rechts + → New repository
  2. Name: poolparty
  3. Sichtbarkeit: Public — bei einem kostenlosen Konto funktioniert GitHub Pages nur so (siehe Kasten unten)
  4. Create repository

2. Die Dateien hochladen

  1. Im neuen Repo auf Add file → Upload files
  2. Am Mac den Ordner _ZUM-HOCHLADEN öffnen, alles darin markieren (⌘ A) und ins Browserfenster ziehen — nicht den Ordner selbst, sondern seinen Inhalt
  3. Unten Commit changes

Die Datei .htaccess brauchst du hier nicht — die versteht nur ein Apache-Server. https macht GitHub von selbst. Die leere Datei .nojekyll dagegen schon: Sie sorgt dafür, dass GitHub die Dateien unverändert ausliefert. Falls sie beim Ziehen nicht mitkommt (versteckte Dateien sieht der Finder erst mit ⌘ + Shift + Punkt), kannst du sie auch im Browser anlegen: Add file → Create new file, als Namen .nojekyll eintragen, nichts hineinschreiben, speichern.

3. Bei IONOS den DNS-Eintrag setzen

  1. ionos.at → Domains & SSL → robschman.at → DNS
  2. Eintrag hinzufügen → Typ CNAME
Typ
CNAME
Hostname
poolpartynur das Wort, ohne robschman.at dahinter
Zeigt auf
robschman.github.ioohne Repo-Namen, ohne https://

Speichern. Die bestehenden Einträge bleiben dabei unberührt.

4. GitHub die Adresse mitteilen

  1. Im Repo poolparty auf Settings → links Pages
  2. Bei Build and deployment: Source Deploy from a branch, Branch main, Ordner / (root) → Save
  3. Bei Custom domain eintragen: poolparty.robschman.at → Save

GitHub legt daraufhin selbst eine Datei namens CNAME im Repo an — das gehört so, genau wie bei robschman.at.

5. Auf den grünen Haken warten

GitHub prüft jetzt, ob der DNS-Eintrag stimmt. Sobald ein grüner Haken bei der Domain steht, erscheint darunter das Kästchen Enforce HTTPS — das ankreuzen. Erst dann läuft die Seite verschlüsselt.

Das dauert

Meist eine halbe Stunde, laut GitHub kann es aber bis zu 24 Stunden dauern, bis „Enforce HTTPS“ auswählbar wird. Bis Freitag ist das kein Problem — aber mach es heute, nicht am Donnerstag.

Zum „Public“-Repository

Der Programmcode wäre damit öffentlich lesbar — also auch die Lösungen. Ehrlicherweise: Das sind sie ohnehin. Bei jeder Seite dieser Art kann man im Browser den Quelltext anzeigen und die Antworten sehen — egal wo sie liegt. Für 12-Jährige auf einer Geburtstagsfeier ist das kein realistisches Problem.

Wenn es dich stört, kann ich die Antworten verschlüsselt hinterlegen, sodass sie auch im Quelltext nicht lesbar sind. Sag Bescheid, das ist eine halbe Stunde Arbeit.

B

Weg B — IONOS-Webspace

Falls du lieber alles an einem Ort hast

Geht auch: Die Subdomain wird dann wie bei fussfessel-hilfe.at einem Ordner auf dem Webspace zugewiesen. Der Haken ist die SSL-Frage von oben.

  1. ionos.at → Domains & SSL → robschman.at
  2. Im Subdomain-Bereich auf Subdomain erstellen
  3. Name poolparty, Verwendungsart Webspace, Zielverzeichnis /poolparty
  4. SSL prüfen — hier entscheidet sich alles. Steht kein Zertifikat zur Verfügung, bietet IONOS eines gegen Aufpreis an. Dann lieber Weg A.
  5. Dateien per FileZilla in /poolparty hochladen
  6. Erst wenn https nachweislich läuft: htaccess-hochladen-als-punkt-htaccess.txt hochladen und auf dem Server umbenennen in .htaccess

Der wichtigste Unterschied zu Weg A

Hier zeigt die Hauptdomain robschman.at weiter auf GitHub, die Subdomain aber auf IONOS. Das ist völlig in Ordnung — nur darfst du beim Anlegen ausschließlich die Subdomain anrühren. Der A-Eintrag von @ bleibt auf 185.199.108.153.

5

Nachprüfen

2 Minuten

Am Handy aufrufen: https://poolparty.robschman.at — der VIP-Startbildschirm muss kommen, und das Schloss in der Adresszeile darf nicht durchgestrichen sein.

Genauer im Terminal — zeigt, wohin die Adresse verweist:

dig +short poolparty.robschman.at

Bei Weg A soll dort robschman.github.io und eine 185.199.*-Adresse auftauchen.

Und was der Server antwortet:

curl -I https://poolparty.robschman.at

Bei GitHub Pages steht in der Antwort Server: GitHub.com und HTTP/2 200.

Sicherheitshalber auch prüfen, dass deine Hauptseite noch steht:

curl -I https://robschman.at
6

Wenn etwas nicht klappt

Die vier üblichen Fälle

GitHub zeigt kein grünes Häkchen, sondern eine Warnung zur Domain Der DNS-Eintrag ist noch nicht durchgedrungen. Eine Stunde warten, dann in den Pages-Einstellungen einmal Save bei der Custom domain drücken — das stößt die Prüfung neu an.
„Enforce HTTPS“ lässt sich nicht ankreuzen Das Zertifikat wird noch ausgestellt. Kann laut GitHub bis zu 24 Stunden dauern. Warten, nichts umstellen.
Die Seite kommt, aber ohne Gestaltung — nur Text Dann fehlt die Datei .nojekyll oder die Ordner css und js sind beim Hochladen nicht mitgekommen. Im Repo nachsehen, ob alle Ordner da sind.
404 von GitHub Meist ist index.html nicht im Hauptverzeichnis des Repos gelandet, sondern in einem Unterordner. Im Repo muss index.html ganz oben liegen, direkt neben css und js.
